What this is

  
A schema-driven playground for search APIs across 10 providers, with two modes:

  
    
    
  • Playground — each provider is a tab (Brave · Ceramic · Exa · Firecrawl · Octen · Parallel · Perplexity · SerpApi · Tavily · You.com); pick an endpoint, fill a form generated from its schema, and inspect the raw response.
    • 
    
  • Compare — configure up to four endpoints side by side (any provider + endpoint + parameters), type one question, and see each raw response in parallel — the same view as the provider tabs, minus the Browse questions button.
    •

Design principle — one provider, one set of files

  
The goal: if someone wants to work on Perplexity, its code is one clear package, not logic strewn across the server and the frontend. Every provider is a self-contained package that implements a shared contract; the server is a thin dispatcher over a registry; the frontend is a generic renderer with no provider-specific code.


  
competitor_search/
├── providers/            # one package per provider — the core of the app
│   ├── base.py          # the contract: Param · Endpoint · Provider (+ compare)
│   ├── registry.py      # the one list of which providers exist
│   ├── exa/             # every provider/ folder has the same 3 files — Exa shown as example
│   │   ├── __init__.py  # exports the Provider subclass
│   │   ├── provider.py  # ExaProvider: identity, auth, endpoints, call()
│   │   └── endpoints.py # /search /contents /answer schemas
│   ├── youdotcom/       # You.com — search / contents / research / finance_research
│   ├── perplexity/      # Perplexity — search + SSE-streaming agent call()
│   ├── parallel/        # Parallel — search / search-beta / task / entity-search
│   ├── tavily/          # Tavily — search / extract / map / crawl
│   ├── brave/           # Brave — GET query-param (web/news/images/videos/suggest/…/local)
│   ├── serpapi/         # SerpApi — GET /search across engines; ?api_key= query auth
│   ├── ceramic/         # Ceramic — web-scale keyword search; reports executionTime
│   ├── firecrawl/       # Firecrawl — web search + optional per-result scrape (markdown/summary/html)
│   └── octen/           # Octen — search / broad-search / answer / extract
├── app/                 # thin web layer over providers/
│   ├── server.py        # GET /api/providers · /api/questions · /api/search40 · POST /api/call · /api/compare
│   ├── playground.js    # generic renderer — fetches catalog, no per-provider code; Browse questions panel
│   └── index.html       # tabs, form shell, compare picker, this About page
└── comparison/          # benchmark question JSON files (search40, simpleqa, browsecomp, …)


  


  
The core classes providers/base.py

  
Three classes are the whole contract. A new provider is usually just declarative — no imperative code.

  

    
ClassIsKey parts

    
      
ParamOne request-body fieldname, type (string·text·int·bool·enum·csv·date·json·group), values, nested fields for objects. Flags steer the form: required, optional (group enable), deprecated (hidden behind a toggle), advanced (tucked into a collapsed Advanced options group), help (shown inline below the param chip). Renders to a form control; serialized via to_dict().

      
EndpointOne API operationmethod, path, label (METHOD /path — description), docs_url, compare_query_field (marks it selectable in Compare), and its list of Params.

      
ProviderA providerbase_url, auth_header/auth_prefix, key_env, endpoints. call() runs the request (default = plain JSON POST; override for streaming/async); catalog() serializes it for the UI.

    
  

  
Providers differ — Exa is a plain JSON POST with x-api-key; Perplexity's agent is SSE-streaming with Bearer auth; SerpApi uses GET with a query-param key. The base handles the common case; a provider that needs streaming or custom auth overrides call() inside its own package. Consistency from the base, isolation per provider.

The request-body schema has a single source of truth — the provider's Python package. The frontend never hardcodes it; it fetches the catalog and renders. So schema and routing can't drift apart. Any endpoint with a compare_query_field is automatically selectable in the Compare picker.

  
The generated form keeps a clean primary view: param names render as purple monospace chips with inline help text; short fields pair up two-per-row; roomy fields span the row; booleans are toggle switches; and less-common params collapse into Advanced options.


  


  
Adding a provider

  
    
    
  1. Create providers/<name>/ with a Provider subclass and its endpoint schemas.
    2. 
    
  2. Register it in providers/registry.py.
    3. 
    
  3. Add its API key to env.txt.
    4. 
  

  
It then appears everywhere — a playground tab, its endpoint dropdown, generated request forms, and the Compare picker — with no changes to server.py or playground.js. Any endpoint that sets compare_query_field is automatically selectable in Compare. Override Provider.call() only if the API streams, is async, or authenticates unusually.
